# 작업 중 판단 기록

사용자가 "물어볼 게 생기면 합리적으로 판단해서 진행하고, 판단한 내용은 여기 적어두라"고 한 항목들.

## 1. "사러 가기" 링크: 에이블리 제외, 무신사·29CM 두 곳만 사용

- WebFetch 도구가 이번 주 사용량 한도에 걸려서 실제 페이지를 직접 열어 확인할 수 없었음.
- 대신 WebSearch로 각 쇼핑몰의 실제 검색 URL 패턴을 구글에 색인된 진짜 페이지로 확인:
  - 무신사: `https://www.musinsa.com/search/goods?keyword=<검색어>` — 구글에 실제 색인된 다수의 musinsa.com 페이지로 확인됨.
  - 29CM: `https://www.29cm.co.kr/store/search?keyword=<검색어>` — 마찬가지로 실제 29cm.co.kr 페이지로 확인됨.
  - 에이블리(a-bly.com/m.a-bly.com): 검색해봤지만 정확한 검색 URL 파라미터를 못 찾음(모바일 전용 SPA라 구글에 검색 URL이 노출되지 않는 듯).
- **판단**: "지어내지 말고 확실히 열리는 주소로만"이라는 요구가 우선이라, 확인 안 된 에이블리 패턴을 추측해서 넣는 대신 무신사·29CM 두 곳만 쓰기로 함. 사용자가 예시로 든 세 곳("무신사·29CM·에이블리 같은") 중 "~같은"이 예시라는 뜻으로 해석.
- 매핑 기준: 패스트패션/리세일형 브랜드(스파오, 탑텐, 유니클로, 무지, 에이블리, 에이랜드, 시에로)는 무신사로, 디자이너/프리미엄 브랜드(코스, 아크네 스튜디오, 메종 마르지엘라, 구찌, 젠틀몬스터, 칼하트WIP, 폴로 랄프로렌, 아워레가시)는 29CM으로, 스포츠 브랜드(뉴발란스, 뉴에라, 노스페이스)는 무신사로 보냄.
- 검색어는 `브랜드 제품명`을 URL 인코딩해서 넣음. 상품 상세 페이지가 아니라 "검색 결과" 페이지라서, 그 브랜드 제품이 실제로 그 쇼핑몰에 없어도 페이지 자체는 항상 뜬다(검색 결과 0건으로 뜰 수는 있음 — "확실히 열리는 페이지"라는 요구사항은 만족하지만 "그 상품이 거기 있다"는 보장까지는 아님).
- **내일 발표 전 꼭 확인할 것**: 실제 브라우저로 몇 개 샘플 링크를 직접 열어서 진짜 로딩되는지 눈으로 한 번 더 확인 권장 (이 세션은 WebFetch 한도 때문에 못 함).

## 2. 표정 타이밍/말풍선 아바타: 로직은 검증, 눈으로 직접 보진 못함

- 이 세션엔 브라우저 도구(claude-in-chrome)가 없어서(사용자가 어제 설치 안 하기로 함) 실제로 화면에서
  표정이 1초/3초 유지되는지 눈으로 볼 수는 없었음.
- 대신 코드 레벨로 꼼꼼히 확인: `setExpression()`은 "최소 노출 시간이 끝나는 시점에 가장 최신 요청을 적용"하는
  방식의 스케줄러라서, 짧은 시간에 여러 표정 요청이 와도(도구 여러 번 호출 등) 건너뛰지 않고 큐잉됨.
  `node --check`로 문법 확인, 서버 쪽 시나리오 1~6 전체는 에러 없이 통과.
- **내일 리허설 때 꼭 확인**: 실제로 🤔가 1초, 😊/🎉가 3초 보이는지, 말풍선 옆 작은 얼굴이 메시지 내용과 맞는 표정인지 눈으로 체크.

## 3. 기억 저장 안정화 — 85% -> 95%, 완전한 100%는 아님

- `config.memory.policy`에 "최애·사이즈·예산이 나오면 그 즉시 저장"을 명시적으로 추가 (Croche의 memory.save는
  모델이 스스로 트리거하는 내장 기능이라, instructions가 아니라 이 policy 슬롯이 맞는 자리).
- 첫 턴만 20번 반복 테스트(응답 후 7초 대기 기준): **17/20 (85%)**.
- 실패 3건이 전부 "메모리 자체가 비어있음"이라 타이밍 문제인지 진단: 같은 조건으로 15초 대기 후 재조회하니
  **19/20 (95%)**로 올라감 — Croche의 기억 저장이 답변 스트리밍이 끝난 뒤 몇 초 더 걸리는 경우가 있는 걸로 보임.
- **판단**: 서버/모델 쪽을 더 쥐어짜는 대신, 클라이언트에서 message.end 직후 한 번, 4초 뒤 한 번 더
  기억 패널을 다시 불러오게 해서(지연 재조회) 실제 화면에서는 거의 항상 반영되도록 함. 100% 보장은 아니지만
  비용 대비 실용적인 선으로 판단.
- 크레딧 절약 지시가 와서, 모델 비교(여러 모델 x 20회) 같은 추가 반복 테스트는 하지 않음.

## 4. 실제 데이터 교체 (손민수위키 70개 + reCree 521곳)

- 멤버 별명 사전을 실제 로스터로 전부 다시 씀: NCT WISH(리쿠·료·사쿠야·재희·유우시·시온), Stray Kids(리노·한·방찬·승민·창빈·필릭스).
  기존 목데이터용 멤버 이름(켄·신유·소운·현진·아이엔 등)은 실제 데이터에 없어서 지움.
- `member: "단체"`(멤버 전원이 같이 착용/방문) 처리: searchItem은 멤버 필터가 있어도 "단체" 아이템은 항상 매치시키고,
  planRoute는 "단체" 방문을 그룹이 맞으면 "최애가 다녀간 곳"(최고 우선순위)으로 쳐줌 — 목포 코스 테스트에서 이게 핵심이었음
  (목포의 성지 대부분이 "단체" 방문으로 기록돼 있어서, 이 처리가 없으면 최애 우선순위가 거의 작동 안 했을 것).
- `TYPE_PRIORITY`에 없는 타입(실제 데이터엔 명소/한식/해변/체험 등 91개 지역에 걸쳐 다양한 타입이 있음)이
  `indexOf`가 -1을 반환해서 맨 앞으로 새치기하던 버그 발견, 목록에 없으면 맨 뒤로 가게 고침.
- findAlternative가 "3만원 예산"을 기억해서 데모 대본의 예시(3개 대체템)보다 적게(예산 안의 1개만) 보여준 건
  버그가 아니라 의도대로 동작한 것으로 판단 — 예산을 더 정확히 반영한 셈이라 그대로 둠.
- searchItem 결과 5개로 제한(토큰 절약), planRoute는 이미 지역으로 먼저 거르고 있어서 그대로 둠.
- 시나리오 1~6을 데모 대본(docs/demo-script.md) 그대로 한 번 돌려서 전부 통과 확인. 크레딧 절약 지시대로
  반복 테스트는 하지 않음(한 번만 확인).

## 5. 지도 (Leaflet + OSM) — 좌표 데이터는 확인, 실제 렌더링은 눈으로 못 봄

- unpkg CDN으로 Leaflet 1.9.4 로드, API 키 필요 없는 OpenStreetMap 타일 사용.
- 지도 실패 대비: `typeof L === 'undefined'`거나 좌표가 없으면 지도 자체를 안 그리고, try/catch로 감싸서
  실패해도 위의 코스 목록(이미 그려진 상태)은 그대로 남게 함.
- 서버 쪽에서 planRoute가 반환하는 lat/lng가 실제로 숫자(float)인 것까지는 확인했지만, 이 세션엔 브라우저
  도구가 없어서 지도가 실제로 그려지는지, 핀 번호·선·팝업이 맞는지는 눈으로 못 봄.
- **내일 리허설 때 꼭 확인**: 지도가 실제로 뜨는지, 와이파이 없이도(CDN 로드 실패) 코스 목록은 그대로 보이는지.

  열리고 닫히는지, 글꼴이 로드되는지.

## 8. 네트워크 오류 처리

- `/send` fetch 실패(네트워크 오류·HTTP 에러) 시 자동 재시도 없이 "연결이 잠깐 끊겼어, 다시 말해줄래?" 한 번만 안내.
- EventSource(`/events`)는 브라우저가 알아서 재연결을 계속 시도하는데, 끊길 때마다 메시지를 띄우면 스팸이 돼서
  한 번만 띄우고(`connectionLostNoted` 플래그) 다시 연결되면(`onopen`) 조용히 해제.
- 이번 배치(1~5번) 마지막 단계라 전체 시나리오 1~6을 한 번 더 통과 확인하고 커밋. 실제로 네트워크를 끊어서
  테스트하진 않았음(서버가 떠 있는 정상 상태에서만 확인) — 크레딧 절약 + 끊기 테스트는 코드 리뷰로 충분하다고 판단.

## 9. 긴급: 장소 검색이 지역에 매달리던 버그 (findPlaces 추가 + geo.ts)

- 근본 원인 두 가지 발견:
  1. "대구"가 "해운대구"(부산 해운대구)의 부분 문자열이라서, 기존 `area.includes()` 방식 매칭이
     대구를 찾을 때 부산 장소를 끌어옴. region을 토큰 단위(시·도/시·군·구)로 쪼개서 접미사를 뗀 뒤
     **정확히 일치**하는지 비교하도록 `src/geo.ts`에 다시 작성(`placeMatchesArea`, `regionBucket`).
  2. 지역 없이 멤버/그룹만으로 전국을 한 번에 찾는 도구가 없어서, 모델이 서울→인천→부산을 찔러보며
     `planRoute`를 반복 호출하고 있었음. `findPlaces` 신설로 해결.
- 모델이 그룹 별명("위시")을 member 자리에 넣는 경우가 있어서, member로 안 풀리면 그룹 별명인지
  역으로 확인하는 `resolveGroupAlias` 추가 (findPlaces·planRoute 양쪽에 적용).
- aliases.json에 이 데이터셋에 있는 다른 그룹들(BTS/TXT/에스파/세븐틴/아이브 등)도 추가 — 안 그러면
  "에스파" 같은 질문이 영어 캐노니컬명과 안 맞아서 빈 결과가 남.
- "위시 픽" 라벨을 장소의 실제 방문 그룹에서 동적으로 계산(`{그룹명} 픽`, 없으면 "추천 메뉴")하도록 수정.
- 지도가 기억 서랍 위로 튀어나오던 버그: `.route-map`에 `isolation:isolate`를 줘서 Leaflet 내부 z-index가
  밖으로 새지 않게 가두고, 서랍/배경막 z-index를 2000대로 올림 — 브라우저로 직접 보진 못했고 CSS 쌓임
  맥락 원리로만 확인.
- 검증 문장 3개 모두 통과: "시온이 다녀간 곳"(목포 9곳 1위), "에스파 장소"(서울 14곳 등 11개 지역),
  "서울에서 위시 간 곳"(서울 5곳) — 세 번째는 모델이 한 번 더 확인 질문을 한 적이 있었지만 재시도하니
  정상 동작(로직 자체는 직접 호출 테스트로 결정적으로 확인됨).

## 6. 덕메 마스코트: SVG 오리지널 캐릭터, 표정 5개

- 실제 아이돌·기존 캐릭터·응원봉과 안 닮게, 머리 위 동그란 혹 2개 + 원형 몸(틸 #02a5c8) + 얼굴판 하나를
  모든 표정이 공유하고, 눈/입 모양만 바꿔서 기본/think/happy/cheer/sorry 5개 표정을 표현.
- ":sorry:" 마커를 새로 추가 (markerGuide + instructions) — "아직 확인되지 않은 정보"라고 답할 때(시나리오 6)
  전용으로 씀. 실제로 호출해서 markers:["sorry"] 뜨는 것까지 확인.
- 표정 바뀔 때마다 살짝 튀는 바운스 애니메이션(헤더 아바타 + 말풍선 옆 미니 아바타 둘 다).
- 서버 쪽 시나리오 1~6은 전부 정상(에러 없음) 확인했지만, 실제로 SVG가 예쁘게 보이는지는 역시 브라우저가 없어서
  눈으로 못 봄 — 내일 꼭 확인.
